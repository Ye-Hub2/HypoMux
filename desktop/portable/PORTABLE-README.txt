============================================================
HypoMux 便携预览版（虚拟网卡预览）说明
============================================================

【这是什么】
这是「免安装」的预览包，用来在不替换、不依赖已安装版 HypoMux 的前提下，
试用新的「创建虚拟网卡」功能。
它由 HypoMux 仓库（GitHub: Ye-Hub2/HypoMux）的构建流水线组装而成，具体版本以
发布页/构建号为准。

请注意：这是预览构建，还没有做过真机端到端验收（详见文末「发布状态」）。

【包内有什么】
hypomux.exe             桌面程序
bin\hypomux-engine.exe  内核引擎
bin\sing-box.exe        网络核心
bin\wintun.dll          Wintun 驱动库
bin\libcronet.dll       核心运行时库
启动便携版.cmd          启动脚本（需要管理员运行）
恢复环境.cmd            恢复脚本
便携版说明.txt          本文件

不要把 bin\ 里的文件挪到外层、改名或删除：程序会按「程序目录\bin\hypomux-engine.exe」
查找引擎，某些情况下还要求它就是安装目录里的那一个文件；布局变了会启动失败。

【运行前提】
1) 必须先把已安装版 HypoMux 完全退出（托盘图标 -> 退出）。
   便携版与已安装版同名、同 UniqueID，同时运行会互相抢占单实例，后启动的一方会静默退出。
2) 右键「启动便携版.cmd」-> 以管理员身份运行。
   本脚本需要停止 HypoMuxCore 服务，而停止服务需要管理员权限。

   为什么**必须**停 HypoMuxCore（这不是可选项）：
   - 便携版的普通会话确实固定用本目录的引擎（不带参数启动，引擎默认执行 serve）。
   - 但「创建虚拟网卡」必须由高权限引擎执行，程序在这条路径上会调用
     EnsureElevated：只有在"已经存在一个管理员引擎会话"时才会复用它，否则它会
     重新拉起引擎，而这条重启路径**优先连接 HypoMuxCore 服务管道**（它会忽略
     便携目录里的引擎路径）。只要 HypoMuxCore 正在运行，连上的就是已安装版的那台
     引擎 —— 它没有虚拟网卡能力，界面会报「当前聚合核心不支持虚拟网卡」。
   - 所以脚本必须先停掉 HypoMuxCore；服务停止后，程序才会用本目录
     bin\hypomux-engine.exe 拉起一台带虚拟网卡能力的管理员引擎。
   - 配合第 2) 条的管理员运行，两者缺一不可。

【首次启动的默认设置（安全优先）】
- 运行模式：系统代理（proxy）
- 不接管系统代理（system_proxy_takeover = false）
- SOCKS5 端口 10800 / HTTP 端口 10801
- 只勾选「以太网」，权重 1
  说明：程序的默认设置是 TUN 模式并且会接管系统代理，首次启动就可能再次影响你的
  网络。所以脚本预置了一份最保守的配置，放在 本目录\data\settings.json
  （如果该文件已存在则不会覆盖，保留你自己的设置）。
- 想用 TUN 模式：请在设置里自己切换（会弹 UAC 提权）。切换前请确认你愿意让程序接管路由。

【新功能：创建虚拟网卡（这次要试的就是它）】
- 入口：首页的「创建虚拟网卡」。
- 当前实现：创建一张 Wintun 虚拟网卡，静态地址 10.66.0.1/24，不接管流量
  （不会自动改动路由把流量导进去），也不会从物理网卡获取 DHCP / 上游地址 ——
  Wintun 是 L3 点对点设备，它不会像桥接那样自动接上你局域网的出口。
- 退出便携版时：适配器随宿主进程消失，相关路由自动回滚。
- 如果提示「当前聚合核心不支持虚拟网卡，请更新 HypoMux 核心后重试」：
  说明当前连上的是已安装版的引擎。退出便携版，确认 HypoMuxCore 已停止，
  再重新运行「启动便携版.cmd」。

【与已安装版的关系】
- 互斥运行（见上面的运行前提）。
- 数据隔离：便携版的数据目录是本包内的 data\（由环境变量 HYPOMUX_DATA_DIR 指定），
  不会读写 %USERPROFILE%\.hypomux，也不会改动 Program Files 下已安装版的文件。
- 但要特别注意：必须通过「启动便携版.cmd」启动。直接双击 hypomux.exe 时不会设置
  数据目录变量，程序会去读用户主目录的 .hypomux 配置（可能正是安装版的配置），
  那样就失去了隔离和「安全种子配置」的保护。

【出问题怎么恢复】
1) 先退出便携版：虚拟网卡随进程消失，路由自动回滚。
2) 想继续用已安装版：运行「恢复环境.cmd」，它会结束便携版残留进程并重新启动
   HypoMuxCore 服务。
3) 还不行就重启电脑；重启后运行「恢复环境.cmd」或直接启动已安装版即可。
4) 本包的脚本不会修改路由表、DNS 和系统代理设置。

【发布状态（如实说明）】
- 构建流水线已执行的门禁：前端依赖安装 / 单元测试 / 前端构建、Go 模块校验、
  单元测试、vet、构建、gofmt、govulncheck、Wails 打包与 NSIS 安装包生成。
- 尚未验收：本包没有在真机上做过端到端运行；虚拟网卡在真实上网场景下的表现
  没有验收；两个脚本的真实提权分支（停服务、UAC 弹窗、进程清理）没有做过运行验证，
  只做过 --check 干跑。
- 结论：这是给人试用的预览包，请不要当作正式发布版。
